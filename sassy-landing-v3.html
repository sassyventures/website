Internal Tool / Strategy

Horizon Roadmap

A multi-user product roadmap built around Now / Next / Later sprint groups. Dynamic grouping, drag-and-drop reordering, job stories, and real-time sync via Supabase.

The problem

Product teams were managing roadmaps in spreadsheets that couldn't group dynamically, show priority at a glance, or capture the thinking behind each initiative.

Questions it had to answer
  1. What are we working on right now vs. later?
  2. Why does each initiative matter?
  3. What's the scope and what does success look like?
  4. How do we capture ideas without losing them?
  5. Can the whole team see the same picture?

Internal Tool / Operations

Deployment Tracker

A multi-launch readiness tracker built for healthcare program rollouts. Four-stage task status, owner assignment, board view across all launches, and live progress reporting. The thinking behind this tool became Runway — the generic version, built for any team launching anything.

The problem

Launching anything across multiple workstreams meant status lived in Slack threads, emails, and memory — no single place showed readiness across every moving part.

Questions it had to answer
  1. What needs to get done?
  2. Who's working on what?
  3. Where's everything at?
  4. What still needs to be done?
  5. Are we ready to launch?

Internal Tool / Experience

Patient Journey Map

A stage-by-stage map of the full patient path from recruitment to active use — every touchpoint, every message, every owner visible in one place. The thinking behind this tool became Wayfinder — the generic version, built for any journey.

The problem

Patient journeys span multiple stages, channels, and owners — but no single view existed to see the full path, making it impossible to know where patients were dropping off or what was missing.

Questions it had to answer
  1. What stages does a patient move through?
  2. What touchpoints and messages exist at each stage?
  3. Who owns each part of the journey?
  4. Where are the gaps?
  5. Is nothing falling through?

How we think

Built on a
short manifesto.

Most tools are built for the average case. Sassy builds for the specific case. One company, one problem, one tool that fits like it was made for it.

We work fast because small things should be fast. We work carefully because the details are the product.

01

Small is a feature

A tool that does one thing well beats a platform that does ten things adequately. Scope is a creative constraint, not a limitation.

02

Bespoke by default

Every app is built for the person using it. No templates. No retrofitting. The brief is the design.

03

Ship it and sharpen it

Fast first version. Refined over time. Better to have a working thing than a perfect spec.

04

The design is the product

How something looks and how it works are the same question. We don't separate them.
